# Check for Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tessera checks for, shows and installs updates via Sparkle 2, on a schedule the person chooses, and releases are published with one script.

**Architecture:** The update preferences are pure settings in `TesseraCore`, mapped to Sparkle values by tested pure functions. A thin `UpdateService` in the app owns Sparkle's updater and applies those values. The UI exposes the check in the About pane, the menu bar and General → Updates. `scripts/release.sh` builds, signs, publishes a GitHub Release and updates `appcast.xml`.

**Tech Stack:** Swift 6, Swift Testing, AppKit/SwiftUI, Sparkle 2 (SwiftPM via XcodeGen), bash, `gh`, Python 3 (stdlib XML) in the release script.

**Spec:** `docs/superpowers/specs/2026-10-05-updates-design.md`

## Review Focus

1. **Changing the frequency or switching auto-checks off in Settings** must take effect immediately, not after relaunch. The pure mapping is tested in Task 1; the live re-apply is checked manually in Task 5.
2. **Beta switched off with a beta installed.** Only stable channels may be allowed. Test `allowedChannels` in Task 1.
3. **No network, or an unreachable feed.** A manual check shows an error; automatic checks stay silent. Manual check in Task 5.
4. **The release script on a dirty tree, or with a version that isn't newer.** It must refuse before building. Covered by Task 4's dry-run checks.
5. **An older settings file without `updates`.** It must load with the defaults and validate. Test in Task 1.

### Task 4: Release script

**Files:**
- Create: `scripts/release.sh` (bash, `set -euo pipefail`, ≤ 200 lines)
- Create: `scripts/appcast_add_item.py` (Python 3 stdlib only, ≤ 150 lines): inserts one `<item>` into `appcast.xml`, creating the file with a valid RSS 2.0 + `xmlns:sparkle` skeleton if it's missing
- Create: `appcast.xml` (empty channel, title "Tessera")

**Interfaces:**
- `scripts/release.sh <version> --notes <file> [--beta] [--dry-run]`
- `python3 scripts/appcast_add_item.py --appcast appcast.xml --version <v> --build <b> --url <url> --length <n> --signature <sig> --notes-file <f> [--channel beta] [--min-system 15.0]`

Script behaviour, in order:
1. Refuse unless the tree is clean and the branch is `main` (`--dry-run` skips the branch check).
2. Refuse unless `<version>` is SemVer (betas `X.Y.Z-beta.N`) and newer than every `sparkle:shortVersionString` already in `appcast.xml`.
3. Build with `CONFIGURATION=Release`, same signing selection as `build-app.sh`, and `MARKETING_VERSION`/`CFBundleShortVersionString` = `<version>`. Reuse `build-app.sh` with an added `TESSERA_VERSION` override rather than duplicating it.
4. `ditto -c -k --keepParent Tessera.app dist/Tessera-<version>.zip`.
5. `sign_update dist/Tessera-<version>.zip`, from the resolved Sparkle `bin/`, and parse `sparkle:edSignature` and `length`.
6. Run `appcast_add_item.py`.
   - Release notes: use Sparkle's Markdown support (`<description sparkle:format="markdown">`) if the resolved Sparkle version has it. Check its docs with Context7 first.
   - Otherwise wrap the notes HTML in CDATA, and say which in the report.
7. Unless `--dry-run`:
   - `gh release create v<version> dist/Tessera-<version>.zip --title "Tessera <version>" --notes-file <file>`, adding `--prerelease` for `--beta`
   - `git commit appcast.xml` and `git push origin main`
   - With `--dry-run`, print the item instead and leave `appcast.xml` unchanged in git.

- [ ] **Step 1: Implement** the three files, and the `TESSERA_VERSION` override in `build-app.sh`, which falls back to `Info.plist`'s value when unset.
- [ ] **Step 2: Verify the dry run** (Bash sandbox off):
